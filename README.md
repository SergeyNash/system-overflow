# System Overflow

Интерактивный прототип о системном мышлении: ограничениях потока, задержках и связях.

## План развития

Следующее направление — коллекция маленьких живых миров, в которых посетитель вмешивается в происходящее и наблюдает последствия. Этапы работы над концепцией, визуальным языком, сценариями, архитектурой и проверкой опыта описаны в [роадмапе «Маленькие миры»](docs/little-worlds-roadmap.md).

Подробный [технический план реализации на английском](docs/little-worlds/technical-implementation-plan.md) описывает архитектуру, контракты, задачи для агентов, зависимости и критерии проверки каждого этапа.

Первый этап описан в [концепции опыта (English)](docs/little-worlds/concept.md): первый визит, действия в кафе, повторные попытки и поведение коллекции. [Текущий статус работы](docs/little-worlds/work-status.md) фиксирует готовые артефакты и следующий этап.

Ниже описана текущая реализация прототипа. Новая концепция пока находится на стадии планирования.

## Эксперимент 01. Узкое место

Система: Вход → A → B → две параллельные ветки C1/C2 → D → Выход.

- На старте очередь возникает перед C1. Ответ заранее не отмечается.
- Можно выбрать любой рабочий узел на графе или кнопками A, B, C1, C2, D.
- Удержание узла 650 мс повышает мощность на одну ступень. Повторное удержание требует отпускания.
- Есть четыре уровня мощности с убывающим приростом: базовая, ускоренная, высокая, предельная.
- Ползунок и кнопки позволяют повышать и уменьшать мощность; они доступны с клавиатуры и на сенсорных устройствах.
- Первое усиление C1 переносит ограничение в D; усиление D — на выход. Повышение мощности других участков может не менять результат.
- Вход и выход — границы модели, их нельзя ускорять.
- После сокращения исходной очереди и появления новой доступен обзор системы и переход к задержке. Повторные действия остаются доступны.
- Пауза останавливает расчёт и движение. Сброс возвращает мощности и очереди к исходному состоянию.

Модель в `flow-model.js` считает накопление очередей во времени и сохраняет количество единиц, включая находящиеся в пути. B распределяет 65% потока в C1 и 35% в C2; D складывает выходы веток. Пропускная способность связей отдельно не моделируется. Очереди не ограничены конечными буферами, потери и обратные связи отсутствуют. Это упрощённая модель для наблюдения за переносом ограничения.

В обзоре `v` показывает текущую обработку, `cap` — мощность, `q` — относительное заполнение очереди (визуальная шкала до 100). Текущий выход сглажен по времени; установившийся выход вычисляется отдельно. Частицы иллюстрируют поток, а не представляют каждую расчётную единицу один к одному.

Другие сцены: интерактивный вход, `02 Задержка`, `03 Связь`, общая карта и свободное исследование.

## Запуск и проверка

Проект статический, без зависимостей и backend. Откройте `index.html` или запустите `python -m http.server 8879`.

Проверка расчётов: `node --test flow-model.test.cjs`.

Подготовка статических файлов для публикации: `node build-static.mjs`. В `dist` попадут только HTML, CSS и два клиентских JS-файла.
